# AI Integration Contract

This document defines the contract between the Application/Data Engine (FastAPI) and the AI Engine.
The goal is to maintain a strict decoupling so that the FastAPI backend remains unaware of LangGraph or Ollama internals.

## Submitting a Task

The AI Engine accepts tasks matching the `AITaskInput` format. When FastAPI receives a request from the frontend, it should construct and pass this object to the AI Execution layer.

```json
{
  "task_id": "unique-uuid-1234",
  "task": "Analyze this company policy and create a summary PDF.",
  "task_type": "analysis",
  "capability": "general",
  "input_data": {},
  "files": ["/path/to/policy.txt"],
  "options": {"output_format": "pdf"},
  "metadata": {"user_id": "5678"}
}
```

## Tracking Task Status

The AI Engine manages states internally. For long-running tasks, the backend can poll or receive callbacks with the following statuses:

- `queued`
- `analyzing`
- `routing`
- `executing`
- `retrieving`
- `verifying`
- `generating`
- `completed`
- `failed`
- `needs_approval`

## Receiving AI Output

When a task concludes, the AI Engine returns an `AITaskOutput` structure. This contains all information required by the frontend.

```json
{
  "task_id": "unique-uuid-1234",
  "status": "completed",
  "answer": "The company policy emphasizes a strict zero-trust model...",
  "model_used": "llama3",
  "sources": ["/path/to/policy.txt"],
  "files": [
    {
      "path": "/absolute/path/to/local_outputs/summary.pdf",
      "format": "pdf",
      "filename": "summary.pdf"
    }
  ],
  "verification": {
    "status": "passed",
    "confidence": 0.95,
    "issues": [],
    "evidence": ["policy.txt"],
    "notes": ["RAG context utilized."]
  },
  "errors": [],
  "metadata": {}
}
```

## Frontend Display Guidelines

The backend should pass the `AITaskOutput` directly or shape it for the frontend:

1. **Answer**: Display the primary text from `answer`.
2. **Generated Files**: Display links to download files using the `files` array. The backend should serve these local paths.
3. **Sources**: If `sources` exist (from RAG), display them as citations.
4. **Model Used**: Present a badge showing `model_used` (e.g., "Generated by llama3").
5. **Verification Status**: Display an indicator based on `verification.status` (green for passed, yellow for requires_review, red for failed).
6. **Errors**: If `status == "failed"`, prominently display the `errors` array.
